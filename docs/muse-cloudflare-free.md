# Muse Cloudflare free preview

This adds an optional read-only provider to the existing admin drawer. It is
not active merely because the source or AI binding has been deployed.

## Activation

1. Verify the target account is on **Workers Free**, not Workers Paid. The
   connector's OAuth cannot read the billing subscription; use the dashboard.
   Do not upgrade, add payment details or change billing to activate this mode.
2. Confirm Cloudflare Workers AI's current account-wide free daily allowance
   and model availability. At review time the platform supplies 10,000 neurons
   per UTC day; Free accounts fail at the cutoff rather than billing overages.
3. Deploy the reviewed source with the `MUSE_AI` AI binding and existing
   `MUSE_AI_RATE_LIMITER`. No OpenAI credential is used by this mode.
4. Set `MUSE_AI_PROVIDER=cloudflare-free`,
   `MUSE_CF_FREE_PLAN_CONFIRMED=true` and `MUSE_AI_ENABLED=true` only after
   verification. Leave `MUSE_PROJECT_GUIDE_ENABLED=false`.
5. Run a synthetic provider smoke test, then authenticated admin acceptance.
   Verify anonymous/client denial, answer/source consistency, partial evidence,
   cancellation and quota errors. Do not run scans or send messages.

The free-plan confirmation is a deployment attestation, **not a runtime billing
detector**. Clear it and disable Muse before upgrading the account to Workers
Paid. This implementation intentionally cannot promise free inference on a Paid
account: Cloudflare can bill account-wide usage over the free allowance there.
If the account is already Paid or its plan cannot be verified, leave this mode
disabled; it needs a separate authoritative spend control before activation.

## Request bounds

- Same active-admin, same-origin, JSON, byte, user-session/RLS and owner-rate
  checks as conversational Muse. No new database migration or privileged client.
- Fixed model: `@cf/meta/llama-3.1-8b-instruct-fp8`, verified in the current
  Cloudflare model catalog and model schema. No configurable model URL, gateway,
  external-provider call, model-directed tool execution, retry or paid fallback.
- Server intent routing selects one existing reader; ambiguous questions use
  studio overview. This is deliberately simpler than the OpenAI tool loop.
- Partial evidence, missing counts, empty reader rows and oversized evidence
  do not invoke inference. Existing overview summaries can contain empty area
  wrappers and still be summarized; these preserve the exact coverage counts.
- Maximum 24,000 UTF-8 request bytes, one provider request, 700 output tokens,
  20-second provider deadline within a 45-second request deadline, and a
  64,000-byte response stream limit. Older history is dropped first; evidence
  is never silently truncated. Provider usage at the output cap is rejected
  because this model does not expose a finish reason.
- Cloudflare's platform enforces the daily allowance across the whole account,
  not per owner. The existing six-per-minute owner limiter is approximate and
  does not implement a daily neuron counter. A 429 is reported as unavailable
  allowance/rate capacity; it is not proof the daily budget was exhausted.
- Model text is untrusted and may be inaccurate. Verified sources and coverage
  are supplied by the server, not generated by the model. Free-preview replies
  are visibly labeled. All project-plan generation/application is blocked in
  this mode, even if its separate flag was accidentally enabled.

## Verification

`npm run verify:muse` includes five new runtime groups for server routing,
no-inference evidence failures, output validation, missing binding/plan guard,
and success/quota/provider failure through the real route with zero OpenAI calls.
These use synthetic data and injected AI responses; they are not live quality
evaluations. Typecheck, full production bundle and a real provider acceptance
test remain necessary before activation.
